# `morph_pillars`: solve pillar displacements

`morph_pillars` is the grid engine: it knows about a CPG pillar lattice,
targets, smoothness, and validity, but not about what a fault means. Fault
semantics and trace-to-target conversion live in `fault_projections`.

## Syntax

```python
morph_pillars(
    grid: CornerPointGrid,
    targets: PillarTargets,
    *,
    w0: float = 0.3,
    boundary: str = "slide",
    boundary_scope: str = "active",
    support_rings: int | None = None,
    normal_only: bool = True,
    smoothness: str = "elastic",
    poisson: float = 0.3,
    stiffness: numpy.ndarray | None = None,
    stiffness_iterations: int = 0,
    stiffness_power: float = 1.0,
    band_rings: int | None = None,
    band_softness: float = 0.02,
    write_tol: float = 1e-9,
    min_fraction: float = 0.10,
    max_bisect: int = 20,
    w_max: float = 1e6,
    polish: str = "none",
    polish_fidelity: float = 4.0,
    polish_size: float = 0.0,
    polish_shape_size: float = 0.0,
    polish_ortho: float = 0.0,
    polish_iterations: int = 200,
    validity_scope: str = "active",
    on_invalid: str = "warn",
) -> MorphResult
```

The full signature is shown because parameters that appear cosmetic can change
the domain outline, displacement support, accepted validity policy, and
fault-fit/quality tradeoff.

## Inputs

`grid` is the parsed `CornerPointGrid`. `targets` is a
`cpg2unstructured.morph.PillarTargets` with one row per target incidence:

| Member | Required shape | Meaning |
|---|---|---|
| `ij` | `(M,2)` integer | Zero-based `(i,j)` pillar lattice index |
| `xy_top` | `(M,2)` float | Desired XY for each top endpoint |
| `xy_bot` | `(M,2)` float or `None` | Optional bottom endpoint target |
| `weight` | `(M,)` float or `None` | Optional nonnegative row weights; default 1 |

If `xy_bot is None`, the movement is rigid: top and bottom endpoints receive
the same displacement, preserving existing pillar slant. Supplying bottom
targets lets the endpoints move independently. Duplicate rows are meaningful:
they represent multiple target incidences, such as both sides of a kink.

## Main controls

| Option | Accepted forms and effect |
|---|---|
| `w0` | Positive dimensionless starting smoothness weight. A larger weight typically reduces target fidelity to preserve smooth displacement. |
| `boundary` | `"slide"` (default), `"pinned"`, or `"free"` for boundary degrees of freedom. |
| `boundary_scope` | `"active"` or `"lattice"` boundary definition; active columns can make a different rim from the full rectangle. |
| `smoothness` | `"elastic"` (default) or `"laplacian"`. |
| `support_rings` | `None` leaves the whole lattice available; an integer pins pillars outside that many rings from the target support. |
| `normal_only` | `True` (default) constrains displacement normal to each target line; `False` constrains the target point. |
| `validity_scope` | `"active"` (default) tests live columns; `"lattice"` tests the whole lattice. |
| `on_invalid` | `"warn"` (default), `"raise"`, or `"ignore"` if no valid weight is found before bracket exhaustion. |
| `polish` | `"none"` (default) or `"barrier"` for optional second-stage shape optimization. |
| `min_fraction` | Default minimum neighboring-pillar separation as a fraction of original spacing. |

Elastic smoothness, stiffness, sacrificial-band options, and polish parameters
control *where* distortion is spent; none change the CPG topology. `write_tol`
zeros very small displacements before writing the result. See source docstrings
for the full tradeoffs and parameters.

## Outputs

`MorphResult.grid` is a new `CornerPointGrid`; the input is not edited.
`d_top` and `d_bot` each have shape `(NX+1, NY+1, 2)`. Other useful members:

- `w`: smoothness weight actually used, including any validity bisection;
- `validity`: `ValidityReport`; `.ok` forwards to `validity.ok`;
- `residuals`: `(M,)` remaining target errors;
- `iterations`, `bisection_steps`, `bracket_exhausted`;
- `polish`: optional polish report;
- `summary()`, plus `n_moved`.

The operation changes lateral pillar XY positions. `ZCORN` and the logical
grid/cell topology are not regenerated by this solver.

## Source-based usage pattern

This excerpt follows the tested trace-to-target-to-morph call sequence; `grid`
and `trace` must already exist in the same coordinate frame.

```python
from fault_projections.targets import targets_from_polyline
from cpg2unstructured.morph import morph_pillars

targets = targets_from_polyline(grid, trace)
result = morph_pillars(
    grid, targets,
    w0=0.05,
    boundary="pinned",
    smoothness="elastic",
    validity_scope="active",
    on_invalid="raise",
)
if not result.ok:
    raise RuntimeError(result.validity.summary())
```

Source-based variants:

- Choose `boundary="pinned"` when preserving the footprint is more important
  than reaching the trace. Use `"free"` only if changing the outline is
  explicitly acceptable.
- Choose `boundary="slide"` only with attention to outline shape; see known
  defect below.
- Set `polish="barrier"` for a second-stage optimization, but independently
  compare target residuals and quality.
- Use `support_rings` when untouched pillars outside a local band are required;
  expect more concentrated strain at its edge.

## Failure modes and limitations

- Unknown boundary, polish, validity-scope, or invalid-result modes raise
  `ValueError`.
- The solver first tries `w0`; if invalid, it searches/bisects toward larger
  smoothness. When no valid result exists up to `w_max` or after the bisection
  limit, default `"warn"` returns a best attempt that may be invalid. Always
  inspect `.ok`; use `"raise"` in fail-fast pipelines.
- Validity is geometric and its default does not reject every near-degenerate
  cell. Consider `min_scaled_jacobian` through a separate
  `check_validity` call and inspect `cell_quality`.
- The existing source/wiki documents a `boundary="slide"` issue on
  non-axis-aligned outlines: index-space tangents can move the physical
  boundary even when validity succeeds. Prefer `pinned` for such outlines and
  measure outline displacement.
- `polish="barrier"` is opt-in and can trade target fit for cell shape; field
  probes in the sibling wiki include bottom-plane cases where polish is
  rejected.
- This is geometric XY adaptation, not fracture propagation, geomechanics,
  transmissibility calculation, or a flow solve.

## Maturity

The engine is implemented and has targeted tests for validity scope,
exhaustion/warning behavior, and target-driven movement. Synthetic-grid
evidence is stronger than general field-deck evidence. Treat its numerical
output as an adaptation candidate that needs independent geometry, corridor,
and simulator checks.
