Corner-point grids, fault projection, and deformation

A practical wiki for cpg2python (the importable cpg2unstructured package) and fault-projections (the importable fault_projections package). Learn which library owns each operation, run small examples, then decide what can safely move into a reservoir workflow.

Versioned snapshot, not a promise of production readiness. Both inspected checkouts are on clean local main branches with latest commits dated 29 July 2026. The examples below distinguish documented tests/benchmarks from anything executed for this guide. An ok result alone does not certify a simulator-ready FAULTS deck.

2 · A mental model before the code

Corner-point grid (CPG)

A logical NX × NY × NZ collection of cells. COORD describes pillar endpoints; ZCORN describes cell-corner depths; ACTNUM switches cells on/off. A column can pinch out or sit across a fault.

Unstructured mesh

Explicit XYZ nodes, cell corners, faces and neighbors, including split faces at non-matching fault depths, plus non-neighbor connections (NNCs) across collapsed layers. Logical (i,j,k) positions remain recoverable.

Fault as cell faces

Eclipse FAULTS identifies faces by 1-based cell indices and direction; it is not a general 3D mesh file. Projecting a smooth geological fault onto a fixed mesh makes a staircase.

Fault-driven morph

Choose which pillars a trace claims, move their XY coordinates toward that trace, spread distortion through neighboring pillars, reject invalid cells, and optionally polish cell shape. The pillar lattice and ZCORN remain unchanged.

Coordinates and indexing: APIs generally use NumPy zero-based arrays internally; emitted Eclipse FAULTS records are one-based. Eclipse Z usually increases downward. Fault grid geometry and deformation are not fracture growth, flow simulation, transmissibility calculation or a geomechanical stress solve.

4 · One small end-to-end example

This route uses the bundled 5 × 5 × 3-cell text grid (XY extent 0–5; 36 pillars). The interior trace below is a worked input, not a recorded golden result. Read the checks before exporting anything for simulation.

import numpy as np
from pathlib import Path
from cpg2unstructured import read_grdecl, from_grdecl, build_topology, write_grid_include
from fault_projections.adapt import adapt_grid

root = Path("/mnt/c/projects/library-development/cpg2python")
grid = read_grdecl(root / "examples/quickstart.grdecl")
mesh = build_topology(from_grdecl(grid))
print("logical dimensions:", mesh.cart_dims, "active cells:", mesh.n_cells)

# This trace is inside the bundled grid; substitute your authored fault.
trace = np.array([[1.0, 1.0], [3.0, 3.0]], dtype=float)
result = adapt_grid(
    grid, trace, w0=0.05, boundary="pinned",
    smoothness="elastic", polish="barrier",
    regenerate_faults=False, on_invalid="raise",
)
assert result.ok, result.morph.validity.summary()
corridor = result.corridor(trace)
assert corridor.ok, corridor.summary()
print(result.summary())
write_grid_include(result.grid, "adapted-coord.grdecl")
Worked input, not a benchmark: substitute your own authored fault in the same coordinate frame; do not treat a passing assertion as simulator qualification. regenerate_faults=False is deliberate: the current topology reconstruction fails on some real decks. The output is an INCLUDE with updated COORD, not a stand-alone complete simulator deck.

5 · Loading a grid

Text: GRDECL

from cpg2unstructured import read_grdecl, from_grdecl
grid = read_grdecl("reservoir.grdecl")
cube = from_grdecl(grid, pinch_tol=0.0)

The parser accepts Eclipse geometry and active-cell keywords, nested INCLUDEs, and selected cell properties. from_grdecl assembles the corner cube and handles inactive and pinched cells. Feed the returned cube into build_topology.

Binary: EGRID or FEGRID

import numpy as np
from cpg2unstructured import read_egrid, from_grdecl, build_topology
grid = read_egrid("FIELD.EGRID")  # MAPAXES applied by default
cube = from_grdecl(grid)
mesh = build_topology(cube)
raw_local = read_egrid("FIELD.EGRID", apply_mapaxes=False)  # warns if MAPAXES exists
wide = read_egrid("FIELD.EGRID", dtype=np.float64)

The reader uses resfo, returns float32 by default, and returns a CornerPointGrid suitable for both adaptation and from_grdecl → build_topology. Despite its name, from_grdecl accepts either reader: Grdecl is a type alias for CornerPointGrid, not a separate text-only type. See grid input and EGRID demo.

Coordinate frame: read_egrid applies MAPAXES by default; the include writer refuses an already MAPAXES-applied grid unless you explicitly set allow_mapaxes_applied=True. Do not write those world coordinates back into a deck expecting its original local frame without checking the simulator's MAPAXES interpretation.

6 · Explicit topology, geometry, and navigation

from cpg2unstructured import (
    read_grdecl, from_grdecl, build_topology, attach_props,
    cell_adjacency, shortest_path,
)

g = read_grdecl("cpg2python/examples/quickstart.grdecl")
mesh = attach_props(build_topology(from_grdecl(g)), g)
print(mesh.nodes.shape, mesh.faces.neighbours.shape, mesh.n_cells)
print(mesh.original_ijk[:3], mesh.nnc.shape, mesh.component.shape)
if "PORO" in mesh:
    print(mesh["PORO"].mean())

graph = cell_adjacency(mesh, weights="unit")
distance, path = shortest_path(graph, 0, mesh.n_cells - 1)
print(distance, path)
parts = mesh.split()  # connected subgrids; useful when ACTNUM creates islands

mesh.cell_faces maps each active cell to six directional face slots; mesh.index_map converts active IDs to logical indices. mesh.nnc can store non-neighbor links across pinch-outs. Faulted i/j neighbors with non-matching Z can produce additional faces; see limitations before using this on large field decks. shortest_path_fast and cell_adjacency_csgraph use the optional SciPy backend.

7 · The 3D surface building blocks

The low-level grid library also exposes a 3D node-edge graph, face-edge incidence, oriented boundaries, plane geometry and prescribed-boundary filling. These are the primitives beneath fault_projections.project_fault_surface and project_quad_mesh_surface; most users should start with those higher-level calls rather than assemble a surface manually.

Grid nodes + edges → snap candidate polygon / mesh skeleton ↓ one discrete edge path per input edge ↓ face set whose boundary equals the projected loop ↓ X/Y/Z FAULTS faces + VTK

For adjoining 3D fault quads, project the shared edge once. Filling each quad independently can leave a seam; a shared skeleton plus prescribed-boundary fill makes inner edges cancel under mod-2 union. A surface's boundary loop is computed from its actual face set, not guessed from the continuous polygon.

8 · A 2.5D fracture line → Eclipse FAULTS

“2.5D” means a 2D XY polyline is projected to mesh faces and then extruded through all NZ layers. It does not infer a depth-varying fault. The sample uses the bundled 0–5 XY grid; on that grid it writes four face records through three layers.

import numpy as np
from cpg2unstructured import read_grdecl, from_grdecl, build_topology, projected_topology
from fault_projections import (
    build_projected_graph, project_polylines, stitch_paths,
    path_to_faults, faults_text,
)

grid = build_topology(from_grdecl(read_grdecl(
    "/mnt/c/projects/library-development/cpg2python/examples/quickstart.grdecl"
)))
top = projected_topology(grid, "xy")
graph = build_projected_graph(top)
lines = [np.array([[1., 1.], [3., 3.]])]
nodes = project_polylines(lines, graph)  # snap / intersect segments
paths = stitch_paths(nodes, graph)       # shortest paths along mesh edges
faces = [path_to_faults(path, top) for path in paths]
text = faults_text(faces, nz=grid.cart_dims[2])
print(text)  # inspect before adding to a simulation deck

Alternatively ingest ESRI shapefile polylines with read_shapefile(...) and as_polylines(...) (optional pyshp). This projection leaves the grid unchanged, so the faces can still be stair-stepped relative to the geological trace. For a straightened grid, use adaptation and validate the resulting face chain.

9 · Fault surfaces in 3D

One planar polygon

import numpy as np
from cpg2unstructured import read_grdecl, from_grdecl, build_topology
from fault_projections import project_fault_surface, write_faults_3d, vtk

grid = build_topology(from_grdecl(read_grdecl(
    "/mnt/c/projects/library-development/cpg2python/examples/quickstart.grdecl"
)))
polygon = np.array([[2,0,0], [2,5,0], [2,5,3], [2,0,3]], dtype=float)
surface = project_fault_surface(polygon, grid)  # explicit UnstructuredGrid
write_faults_3d("FAULTS.txt", [("F1", surface)], grid)
vtk.write_fault_vtk("inspection", grid, surface, polygon=polygon)

Input is a planar closed polygon. The surface is selected from 3D cell faces, preserving layer-specific K and X/Y/Z directions; its reported boundary is the discrete surface's own rim. The example selects 14 faces on the bundled grid and writes FAULTS.txt plus files under inspection/. Inspect the VTK output before interpreting the FAULTS records physically.

Curved or piecewise-planar fault

facet_surface can split a curved height function or point cloud into planar quads. project_faceted_surface unions the projected facets, but independently projected adjacent quads can disagree along a shared edge. For a coherent quad surface mesh, use QuadMesh, project_mesh_skeleton and project_quad_mesh_surface: shared edges are projected once and the per-patch boundaries are filled consistently. Branching faults (more than two patches along an edge) are rejected rather than treated as a manifold surface.

Run a complete two-quad fixture: the repository example constructs six vertices and two quads sharing an edge, projects them onto a synthetic grid and writes FAULTS + VTK:

cd /mnt/c/projects/library-development/fault-projections
python3 examples/quad_mesh_fault.py --out quad-demo
# Optional: --polish; inspect the printed "interior holes" count.

That command produced 208 faces and zero interior holes with its default fixture in the local check; a naïve two-facet projection would not enforce a shared seam. Import QuadMesh and project_quad_mesh_surface(mesh, explicit_grid, graph) to embed the same sequence in code. The bundled quickstart grid contains inactive cells and is not a drop-in substitute: a sample ridge on it raised BoundaryDoesNotBound. Build and validate a suitable Cartesian/field fixture first.

See the algorithm guide, boundary rule, and the example directory for actual input construction and figure exports.

10 · Fault-driven deformation, carefully

The grid package does not understand geological faults. The projection package turns traces/polygons into PillarTargets; the grid package moves pillars. Moving COORD leaves the corner-point lattice and ZCORN intact, and distorts surrounding cell shape. It does not remesh or add resolution.

2D XY trace → targets_from_polylines → identical XY shifts at both pillar ends 3D planar polygon / quad facets → depth-varying targets → top and bottom move independently ↓ morph_pillars → MorphResult.grid adapt_grid → AdaptResult.grid ↓ cell validity + corridor + face chain + physical outline

High-level: a trace into an adapted grid

import numpy as np
from cpg2unstructured import read_grdecl, write_grid_include
from fault_projections.adapt import adapt_grid

original = read_grdecl("model.grdecl")
trace = np.array([[120., 80.], [340., 510.]])
adapted = adapt_grid(
    original, trace,
    w0=0.05, boundary="slide", boundary_scope="active",
    smoothness="elastic", poisson=0.3,
    polish="barrier", polish_fidelity=4.0,
    validity_scope="active", on_invalid="raise",
    regenerate_faults=False,
)
assert adapted.ok, adapted.morph.validity.summary()
corridor = adapted.corridor(trace)  # checks adapted.grid, not original
assert corridor.ok, corridor.summary()
print(adapted.summary())
write_grid_include(adapted.grid, "adapted-grid.grdecl")
Choose boundary="pinned" for sheared or non-axis-aligned outlines. The documented slide implementation uses lattice-index tangents instead of geometric boundary tangents; it can move the actual outline while reporting success. Default slide is appropriate only after checking the outline and its post-morph displacement. free deliberately changes model extent.

Low-level: explicit targets and solver

from cpg2unstructured import morph_pillars, write_grid_include
from fault_projections import targets_from_polyline

targets = targets_from_polyline(original, trace, consolidate=True)
out = morph_pillars(
    original, targets, w0=0.05, boundary="pinned",
    smoothness="elastic", polish="barrier",
    validity_scope="active", on_invalid="raise",
)
assert out.ok, out.validity.summary()
print(out.summary())
write_grid_include(out.grid, "adapted-grid.grdecl")

Use targets_from_polylines to solve several faults together rather than repeatedly morphing an already-morphed grid. targets_from_polygon handles a dipping plane; targets_from_facets targets a faceted surface. Those depth-varying 3D target workflows need extra scrutiny on tilted pillars: top and bottom validity can diverge. In the low-level example out is a MorphResult; high-level adapt_grid instead returns an AdaptResult with its solver result under .morph.

Stage 2: a dipping plane changes top and bottom differently

import numpy as np
from cpg2unstructured import read_grdecl, pillar_lattice
from fault_projections import adapt_grid

original = read_grdecl(
    "/mnt/c/projects/library-development/cpg2python/examples/quickstart.grdecl"

    [2.2, 0., 0.], [2.2, 5., 0.],
    [2.8, 5., 3.], [2.8, 0., 3.],

    original, polygon, boundary="pinned", w0=0.05,
    regenerate_faults=False, on_invalid="raise",

Deforming the grid and projecting a 3D FAULTS surface are distinct steps: this call does not produce the latter.

What the optimizer does

  1. Claim: select an ordered, connected lattice-pillar chain close to the trace, including endpoints. Never move both ends of every crossed edge onto the line: that can weld cells.
  2. Target: assign claimed pillars the nearest points on the finite fault segments; consolidate contradictory claims. A point already on the fault must stay constrained.
  3. Solve: minimize target misfit plus weighted Laplacian or linear-elastic smoothness over pillar XY moves. Unclaimed pillars share the deformation.
  4. Reject/repair: check folds, near-welds and top/bottom crossings; adjust the smoothness weight if needed. Always inspect .ok and the validity report.
  5. Polish (opt-in): use a barrier energy relative to each cell's original shape to rescue flattened but uninverted cells. Inspect both planes and the remaining fault misfit.

The objective is mean(target misfit²) + w × mean(deformation energy). Smaller w0 follows the fault more closely; larger values protect cell shape. The solver can increase the effective w to find a valid grid; the final value and attempt history live in MorphResult.

11 · Deformation controls and trade-offs

These are solver-tuning knobs, not guarantees of valid output: change one at a time and rerun the four gates.

What should I choose? A conditional recommendation

Best-supported default, not a universal winner: on an axis-aligned grid, begin with smoothness="elastic", w0=0.05, polish="barrier", boundary_scope="active", validity_scope="active" and on_invalid="raise". Use boundary="pinned" for an interior fault; use "slide" only when a fault touches an axis-aligned rim and tangential movement is acceptable. For a sheared or rotated outline, choose "pinned" even for a rim-touching fault. For large real decks with the documented topology blocker, specify regenerate_faults=False and do not claim generated FAULTS. Run all four gates; the 0.3 scaled-Jacobian floor is not a built-in default.

Copyable starting point for the bundled interior trace (change the trace, units and gates for your own deck):

import numpy as np
from cpg2unstructured import (
    read_grdecl, pillar_lattice, cell_quality, check_validity, active_columns,
)
from fault_projections import adapt_grid

grid = read_grdecl(
    "/mnt/c/projects/library-development/cpg2python/examples/quickstart.grdecl"
)
trace = np.array([[1., 1.], [3., 3.]])
result = adapt_grid(
    grid, trace, boundary="pinned", boundary_scope="active",
    validity_scope="active", smoothness="elastic", w0=0.05,
    polish="barrier", on_invalid="raise", regenerate_faults=False,
)
assert result.ok, result.morph.validity.summary()
corridor = result.corridor(trace)
assert corridor.ok, corridor.summary()
original = pillar_lattice(grid)
adapted = pillar_lattice(result.grid)
quality = check_validity(
    adapted, original, active=active_columns(grid),
    min_scaled_jacobian=0.3,
)
assert quality.ok, quality.summary()
print("top:", cell_quality(adapted, plane="top").line())
print("bottom:", cell_quality(adapted, plane="bot").line())
print(result.summary())

Why the old leaderboard winner is not the default: the first 910-run composite ranking put lap_free_polish first (score 0.853), but it did not penalize changes to model extent sufficiently. The later paired boundary study and corrected recommendation establishes that free buys apparent fault fit largely by moving the footprint and that, after polish, elastic and Laplacian fit almost identically; elastic fares better on quality and non-orthogonality. The recommended setting is therefore conditional on the boundary and the output's quality requirements, not the single highest historical score. Evidence is mainly synthetic; even a good synthetic setting is experimental for 3D/tilted, irregular ACTNUM, faulted or full-field grids.

12 · Tested deformation cases: compare before trusting

Each block below is self-contained and uses the bundled cpg2python/examples/quickstart.grdecl (5 × 5 × 3 cells, XY 0–5), not a field model. Run with the same Python environment as the installation; nothing is written to either repository. Numerical assertions target behavior, not exact optimizer output across SciPy versions. These are reproducible demonstrations, not a broader validation campaign.

One input, four solver choices: fidelity versus cell shape

import numpy as np
from cpg2unstructured import (
    read_grdecl, pillar_lattice, cell_quality, check_validity, active_columns,
)
from fault_projections import adapt_grid

grid = read_grdecl(
    "/mnt/c/projects/library-development/cpg2python/examples/quickstart.grdecl"
)
trace = np.array([[1., 1.], [3., 3.]])
settings = {
    "elastic": dict(w0=0.05, smoothness="elastic"),
    "laplacian": dict(w0=0.05, smoothness="laplacian"),
    "stiffer": dict(w0=2., smoothness="elastic"),
    "barrier": dict(w0=0.05, smoothness="elastic", polish="barrier"),
}
for name, kw in settings.items():
    result = adapt_grid(
        grid, trace, boundary="pinned", regenerate_faults=False,
        on_invalid="raise", **kw,
    )
    top = cell_quality(pillar_lattice(result.grid), plane="top")
    bottom = cell_quality(pillar_lattice(result.grid), plane="bot")
    strict = check_validity(
        pillar_lattice(result.grid), pillar_lattice(grid),
        active=active_columns(grid), min_scaled_jacobian=0.3,
    )
    assert result.ok, result.morph.validity.summary()
    print(name, "residual mean", round(float(result.distance_after.mean()), 4),
          "top/bot SJ", round(top.sj_min, 3), round(bottom.sj_min, 3),
          "newly below 0.3", strict.n_degenerate,
          "passes 0.3 gate?", strict.ok)

On the inspected checkout, elastic at w0=0.05 had mean residual ~0.0063 but minimum top scaled Jacobian ~0.058; the explicit 0.3 gate rejected three columns despite result.ok=True. Barrier polish increased mean residual to ~0.062 while lifting the top minimum to ~0.627; a stiffer solve also improved shape at the cost of distance. These numbers are for this synthetic deck only. Compare both endpoint planes, physical fault distance and the explicit quality floor before choosing a setting; check_validity does not silently impose a 0.3 threshold.

Boundary policy: expose the sheared-outline slide defect

from dataclasses import replace
import numpy as np
from cpg2unstructured import read_grdecl, pillar_lattice
from fault_projections import adapt_grid

base = read_grdecl(
    "/mnt/c/projects/library-development/cpg2python/examples/quickstart.grdecl"
)
# Shear BOTH pillar endpoints: x_world = x_local + 0.5 * y.
coord = base.coord.copy()
coord[:, 0] += 0.5 * coord[:, 1]
coord[:, 3] += 0.5 * coord[:, 4]
grid = replace(base, coord=coord)
trace = np.array([[1.1, 2.2], [6.7, 3.4]])  # transformed rim-to-rim trace

for mode in ("pinned", "slide", "free"):
    result = adapt_grid(
        grid, trace, w0=0.05, boundary=mode,
        regenerate_faults=False, on_invalid="raise",
    )
    xy = pillar_lattice(result.grid).top
    # Original physical outline: x-0.5y=0 or 5, and y=0 or 5.
    outline_error = max(
        np.max(np.abs(xy[0, :, 0] - 0.5 * xy[0, :, 1])) / np.sqrt(1.25),
        np.max(np.abs(xy[-1, :, 0] - 0.5 * xy[-1, :, 1] - 5)) / np.sqrt(1.25),
        np.max(np.abs(xy[:, 0, 1])),
        np.max(np.abs(xy[:, -1, 1] - 5)),
    )
    print(mode, "ok", result.ok, "outline error", round(outline_error, 4),
          "mean target residual", round(float(result.distance_after.mean()), 4))
    if mode == "pinned":
        assert outline_error < 1e-9

Observed physical outline errors were 0 for pinned, ~0.158 for slide, and ~0.497 for free; all three returned ok=True. The slide value is the problematic one: tangential motion on an index edge is not tangential to this sheared physical edge. For a different deck, compute distances to its own original outline rather than copying these x/y equations. A lower target residual cannot justify unnoticed changes to the reservoir footprint.

Two crossing traces: solve simultaneous claims, not sequential grids

import numpy as np
from cpg2unstructured import read_grdecl
from fault_projections import adapt_grid, targets_from_polylines

grid = read_grdecl(
    "/mnt/c/projects/library-development/cpg2python/examples/quickstart.grdecl"
)
traces = [
    np.array([[1., 1.], [3., 3.]]),
    np.array([[1., 3.], [3., 1.]]),
]
targets = targets_from_polylines(grid, traces)
claimed = len(set(map(tuple, targets.ij)))
print("target rows", targets.n, "distinct pillars", claimed)
assert targets.n > claimed  # an intersection can carry multiple claims
result = adapt_grid(
    grid, traces, boundary="pinned", w0=0.05,
    regenerate_faults=False, on_invalid="raise",
)
assert result.ok, result.morph.validity.summary()
assert result.distance_after.shape == (targets.n,)
print(result.summary())

This case produced ten target rows across eight distinct pillars and a valid adapted grid. Each conflicting claim contributes a residual; the solver balances them in one system. Calling adapt_grid twice on successive output grids instead changes the starting geometry and can undo the first alignment. Do not interpret result.ok as proof that both geological faults have an acceptable corridor: assess each trace, its residuals, face chain and outline separately.

13 · Reading, writing and preserving FAULTS

The high-level projection pipeline can generate Eclipse FAULTS/FAULTDIM text, optionally write 3D records, and export VTK for inspection. The inverse utilities faults_from_deck and trace_faults recover plan-view traces from existing Eclipse face records. A recovered trace is not independent ground truth: it runs through its deck's original faces, so “before vs after” distances measured against it can be circular.

from fault_projections import faults_from_deck, trace_faults
from fault_projections.adapt import fault_faces_from_chain, fault_cell_map

named = faults_from_deck("field.DATA")
for name, faces in named.items():
    traced = trace_faults(original, faces)
    print(name, traced.n_components)

# For targets built from an authored trace:
faces = fault_faces_from_chain(targets)
cells = fault_cell_map(targets, original.cart_dims)
assert cells.is_continuous

fault_faces_from_chain reads aligned faces from the claimed pillar walk; it does not need to rerun nearest-node projection on the deformed mesh. fault_cell_map identifies cells on either side of the chain, with (-1, -1) for the outside. Its .is_continuous tests adjacent target pillars, not complete face coverage or geometric validity. MULTFLT transmissibility multipliers are not written by these APIs.

faults_from_deck expands inclusive I/J ranges and deduplicates faces by name; it ignores vertical Z/K faces by default and rejects them with keep_vertical=True. trace_faults retains component, branch, duplicate and out-of-range metadata. fault_polyline returns just the longest chain; choose fault_polylines to retain them all. Neither approach silently fixes a broken fault network.

Export strategy: never replace the master deck with a GRDECL read–write round trip. Unparsed scheduling, region and EDIT keywords may be lost. Export a new COORD INCLUDE and add its INCLUDE 'adapted-grid.grdecl' / reference to a copy of the master deck. Confirm the include order and simulator parsing. The default regenerate_faults=True on adapt_grid/adapt_deck can hit current real-deck topology blockers; choose explicitly.

14 · Four independent gates before using an adapted grid

import numpy as np
from cpg2unstructured import (
    read_grdecl, boundary_mask, pillar_lattice, morph_pillars,
)
from fault_projections import targets_from_polyline
from fault_projections.corridor import cell_corridor
from fault_projections.adapt import fault_cell_map

original = read_grdecl(
    "/mnt/c/projects/library-development/cpg2python/examples/quickstart.grdecl"
)
trace = np.array([[1., 1.], [3., 3.]])
targets = targets_from_polyline(original, trace)
result = morph_pillars(
    original, targets, boundary="pinned", w0=0.05,
    on_invalid="raise",
)
assert result.ok, result.validity.summary()  # 1. valid cells
corridor = cell_corridor(result.grid, trace)  # 2. connected, containing strip
assert corridor.ok, corridor.summary()
assert fault_cell_map(targets, original.cart_dims).is_continuous  # 3. chain

# If extent must not move, check the original active rim in physical XY.
rim = boundary_mask(original, scope="active")
before = pillar_lattice(original).top[rim]
after = pillar_lattice(result.grid).top[rim]
tolerance_metres = 1e-6  # replace with your project's explicit tolerance
assert np.max(np.linalg.norm(after - before, axis=-1)) < tolerance_metres  # 4. fixed rim

This low-level example retains the exact targets used by the solver so the chain gate checks the same claim. High-level adapt_grid does not expose targets on AdaptResult; reconstructing them separately may not capture all multi-trace input choices. Adjust tolerance_metres to your project's units and rim policy. These gates ask different questions: valid cells; a face-connected corridor actually containing the trace; a continuous exported fault chain; and whether the footprint moved. No single ok covers all four.

To compare before and after rather than only the final grid, call cell_corridor(original, trace) from fault_projections.corridor before adaptation and adapted.corridor(trace) afterward. Both use the pillar lattice directly; they do not need build_topology. fault_faces_from_chain(targets) takes only the targets. Check both FaultCellMap.left and .right for out-of-grid sentinels on boundary-touching faults.

Also inspect cell_quality / scaled Jacobian, non-orthogonality (especially for two-point flux), the count of newly sub-0.3 cells, pinched regions, the exported FAULTS records, and field-specific output in a viewer. Do not mistake a validity check for a quality threshold: cells can be nearly flat without being inverted. check_validity(..., min_scaled_jacobian=0.3) adds an explicit quality floor but is off by default.

19 · Troubleshooting and interpretation

My script cannot import either package.

Check that the current interpreter is the environment where both editable packages were installed. The repository cpg2python imports as cpg2unstructured; fault-projections imports as fault_projections. A similarly named proprietary fault_projection package is unrelated.

build_topology fails with “more than 2 neighbours”.

This is a documented real-deck blocker, not evidence that morph_pillars also fails. For a grid-only adaptation, set regenerate_faults=False and validate the output. Do not claim a regenerated FAULTS deck was produced.

result.ok is true but the outline moved.

Validity checks cell geometry, not the original model footprint. On non-axis-aligned outlines slide can move the rim because it uses index-space tangents. Use pinned and explicitly compare physical boundary coordinates.

A result is valid but has very flat cells.

Non-inverted does not imply good quality. Measure scaled Jacobian and non-orthogonality, consider polish="barrier" and an explicit min_scaled_jacobian threshold, and re-check the distance to the actual authored fault.

The fault “improved” by moving the model footprint.

boundary="free" deliberately moves it. Score only non-rim claimed pillars to distinguish genuine alignment from footprint movement; choose slide for an axis-aligned footprint or pinned otherwise.

The generated deck does not include transmissibility multipliers.

FAULTS names fault faces; MULTFLT authoring and simulator-flow calibration remain outside this implementation. Preserve relevant original deck sections and review their consistency separately.
